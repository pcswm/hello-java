**5 错 2 对，但错因只有一个：把 `+` 全当成字符串拼接了。**

第 3、4、7 题的预判结果全是"把两个数接起来"，说明当时的模型是"`+` = 拼接"。真实规则是：**`+` 两边只要有一个是 `String` 才是拼接，两个都是数字就是加法。**

把数字当成拼接的后果很严重：`2147483647 + 1` 这种溢出根本不会被发现，程序会拿着一个负数继续算。

## 今天的五条结论

### 1. `+` 的两副面孔

```java
"结果：" + 5 / 2     // "结果：2"   ← 有 String 才是拼接，但 5/2 先算
5 / 2                // 2           ← 纯数字，真加法
2147483647 + 1       // -2147483648 ← 纯数字，真加法，然后溢出
```

### 2. 整数除法只有一个条件：两个操作数都是整数

```java
9 / 5            // 1    两边都 int，截断
9 / 5.0          // 1.8  一边是 double，不截断
70 / 3.0         // 23.33
weight / (h*h)   // 22.857  ← 左边 int 也一样出小数
```

**不是"按最前面的类型来"。** 左结合只决定先算哪一步，不决定类型；类型由**每一步的那一对操作数**决定，窄的自动提升到宽的。

提升顺序：`byte → short → int → long → float → double`，`char → int`。

反例（危险）：
```java
70 / 3 * 1.0     // 23.0，不是 23.33 —— 截断在第一步就发生了
```

### 3. 温度转换器：69.5 这个错误结果

```java
double f  = c * 9 / 5 + 32;   // 99.5  ✅ c*9 已是 double
double f2 = 9 / 5 * c + 32;   // 69.5  ❌ 9/5 先算成 1
```

括号救不了：`c * (9 / 5) + 32` 同样是错的（37.5 × 1 + 32 = 69.5）。
括号只改变计算顺序，改变不了括号里两个整数的除法性质。

修法：`c * 9.0 / 5 + 32`，或提成常量 `final double RATIO = 9.0 / 5;`。

**为什么这个 bug 危险**：69.5°F ≈ 20.8°C，看起来像个正常温度，程序不报错。

### 4. `i++` 交出旧值，`++i` 交出新的

`i++` 一个动作产生两样东西：
- 变量 `i` 变成新值
- 表达式交出的值是**旧值**

```java
int i = 1;
System.out.println(i++);   // 打印 1（交出的旧值）
System.out.println(i);     // 打印 2（变量本身）
```

| 写法 | 交给外部的值 | 结束后 i |
|---|---|---|
| `i++` | 旧值 | 2 |
| `++i` | 新值 | 2 |
| `arr[i++]` | 下标用旧值，用完前进 | — |
| `arr[++i]` | 下标用新值 | — |

`i++ + ++i`（i 初值 1）= 1 + 3 = **4**，结束后 i = 3。

> 实际开发别写这种代码，可读性差。`i++` 只出现在 `for` 迭代和 `arr[index++]` 这类场景。

### 5. `int` 溢出会绕回负数，而且不报错

`2147483647 + 1` = `-2147483648`。二进制全 1 进位后符号位变负。

而且这是**编译期**就算完的（常量折叠），不是运行时才发生。

涉及大数用 `long`（加 `L`），金额用 `BigDecimal`。

## 其他知识点

- `0.1 + 0.2 = 0.30000000000000004`：二进制存不下 0.1，所有语言都这样。**`double` 不能算钱。**
- `%` 是取余数，不是商：`10 % 3 = 1`，`-10 % 3 = -1`（符号跟被除数）
- 整数默认 `int`，小数默认 `double`；`long` 加 `L`，`float` 加 `f`
- `(int) 3.99` = 3，**截断不是四舍五入**，要四舍五入用 `Math.round()`
- `printf` 的 `%d` 只接整数，传 `double` 会在运行时抛 `IllegalFormatConversionException`
- 类名 PascalCase，变量 camelCase，常量 UPPER_SNAKE_CASE
